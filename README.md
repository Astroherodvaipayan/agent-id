# Campaign Studio · AgntID Hackathon

Campaign Studio coordinates up to three creator negotiations against one campaign budget. A human approves every exact proposal. AgntID sits at the tool boundary: each creator worker opens a task and scoped delegation, then invokes only the reviewed proposal tool through the Runtime. The application separately enforces recipient, wording, approval, round, and shared-budget rules.

**Inspect the integration:** [`app/coordinator.py`](app/coordinator.py) contains task, delegation, approval-digest, and wrapped tool-call code; [`app/runtime_tools.py`](app/runtime_tools.py) verifies exact tool names and schemas; [`app/mcp_server.py`](app/mcp_server.py) exposes the proposal handlers. [`scripts/no_send_mcp.py`](scripts/no_send_mcp.py) and [`scripts/agntid_trust_probe.py`](scripts/agntid_trust_probe.py) provide a reproducible no-email boundary probe. The [trust probe guide](docs/agntid-trust-probe.md) states which Runtime and Reporting evidence is still required. Configured policies and local tests are not presented as completed live enforcement.

## Setup

Install with `pip install -e '.[test]'`. Configure environment variables from `.env.example` in your shell or a local secret manager. Run `uvicorn app.api:app --host 127.0.0.1 --port 8765` for the dashboard and `python -m app.mcp_server` for the tool server. The MCP server refuses to start until the operator configures `AGNTID_TOOL_TOKEN`; it binds to localhost and requires that bearer token on every request. Configure AgntID Runtime to send that token to this MCP server and make `send_nonbinding_proposal` visible to the agent. This controls transport access; it does not itself prove a request traversed AgntID. Configure its numeric inclusive policy cap at **2,500,000 paise** in Access Control > Access Policies > server > tool > Baseline Allow Policy, then confirm Applied sync. The app has a separate 5,000,000 paise ceiling. No real send is attempted until an operator approves a proposal and invokes the send endpoint. SMTP is outbound only; configure IMAP to ingest replies with `POST /inbox/poll`.

The AgntID dependency is pinned to official source SDK 0.2.0 commit `f4fcd2fe476f0c4dcf800e498530b7042b830f6b`, whose task snapshot interfaces were verified locally. See [AgntID setup](docs/agntid-setup.md) for portal and runtime steps.

## Workflow

For the trial, run `.venv/bin/python scripts/run_demo.py`, open `http://127.0.0.1:8765/`, and enter the displayed `demo-local` operator token. This is the original Campaign Studio with an isolated `demo.sqlite3` database. Create and review a real campaign brief, approve the exact backend-generated proposal in Outreach, then use the mock email exchange below it. Real email dispatch and inbox polling are blocked in demo mode. The mock reply can be sent to the configured Gemini model for a genuine negotiation suggestion; the simulated final agreement remains illustrative. The customer-facing recording at `docs/customer-video/campaign-studio-customer-demo.mp4` shows a person filling the campaign fields, reviewing and approving the proposal, viewing the sample creator conversation, using an AI negotiation suggestion, and reaching the partnership summary. An on-screen AgntID note explains where the live agent's send permission and offer limit are checked.

Create a draft with `POST /campaign`, approve its exact proposal with `POST /approve`, then invoke `POST /send`. `GET /` shows the current state. The AgntID task must be accepted and shortlist the send tool before dispatch. Runtime connection, policy sync, SMTP credentials, IMAP credentials, and controlled inbox approval remain operator setup tasks.

`POST /campaign/ai` drafts a brief, budget, suggested creator-facing opening and market-risk findings using the configured Gemini model. `POST /negotiate/suggest` treats a manually verified creator reply as untrusted evidence for a proposed amount and counteroffer opening. Both return 503 while `GEMINI_API_KEY` or `GEMINI_MODEL` is unset. Neither route sends mail or approves an amount. The backend owns recipient, fixed package, price rendering, outbound opening and nonbinding terms. Gemini prose and the campaign idea are review data only; the sent email uses a fixed backend-owned opening. Campaign creation requires target markets; avoid terms block the draft until revised, and brand/operator market review is required before proposal approval. This reduces risk but cannot guarantee that copy will never offend a market.

The local dashboard is at `http://127.0.0.1:8765/` when started with `.venv/bin/uvicorn app.api:app --host 127.0.0.1 --port 8765`. The browser opens a local session automatically; no dashboard password is needed for the loopback demo. Requests are limited to loopback peers and local Host values, and cross-origin mutations are rejected. Existing Bearer token access remains available for local API clients. The local session does not bypass proposal, budget, recipient, or AgntID approval gates. API schemas are at `/docs`. Runtime connection and policy sync must be checked in the operator's AgntID portal; the runnable [trust probe](docs/agntid-trust-probe.md) describes the separate evidence needed for live enforcement claims.

Approval freezes recipient, sender, reply-to, subject, full body, amount and package into a hash-checked snapshot. Reservation and approval checks share one SQLite write transaction. A send timeout stays `unknown` and cannot auto-retry; record provider or operator evidence through `POST /outbox/reconcile` using the stored Message-ID. Provider acceptance and inbox delivery are distinct states. IMAP polling uses read-only `BODY.PEEK` and UIDVALIDITY-qualified UIDs. Incoming messages are quarantined because `From` and mail headers alone are insufficient authentication evidence; an operator records structured provider and thread evidence through `POST /inbox/verify` before the reply can inform model suggestions. Unthreaded replies cannot be verified through that route.

The dashboard exposes exact email preview, market review, approval, send readiness, reply polling and negotiation suggestions. ## Multi-creator negotiation snapshot

The Outreach screen supports creating allowlisted creator lanes, explicit brand reveal, exact email preview/approval, bounded worker dispatch, cancellation, provider reconciliation, reply verification and recording a human-confirmed external agreement. The creator shortlist itself never authorizes an email address. IMAP routes replies by exact Message-ID and matching configured sender; header matching quarantines the reply and does not authenticate or authorize it.

Each worker uses the official SDK task open, accepted-task shortlist, delegation open, wrapped call, delegation close and task close APIs. Root and acting agent IDs must correspond to configured platform identities. Delegation acknowledgements with unknown shapes fail closed; the live runtime response schema is not verified. `AGNTID_REQUIRE_CONTEXTUAL=false` selects Standard intent with no contextual-shortlist claim. Model negotiation suggestions remain separately reviewed and are never arbitrary SMTP tool arguments.

Configure numeric inclusive maximum 2500000 paise on `send_creator_proposal` and verify Applied sync plus Reporting before claiming platform protection. Aggregate campaign-budget enforcement is the backend SQLite transaction, not a verified AgntID aggregate policy. Cancellation only releases a reservation before dispatch. Unknown sends and dispatched proposals retain budget until documented provider reconciliation; duplicates never dispatch again. Cancellation does not retract sent mail or existing external agreements.

Anonymous mode needs separately reviewed neutral From/Reply-To identities; brand-domain matches are rejected, and provider header rewriting must be independently checked. Revealed mode requires explicit operator evidence and invalidates prior approval. Negotiation is bounded to three rounds and four hours per creator. A new verified reply to the current proposal, verified supersession evidence and a model suggestion precede each new round; every exact revised email requires operator approval. Any active or unknown campaign send blocks round preparation. The old budget hold stays until an atomic approved replacement reservation; a failed replacement leaves the old hold intact. Campaign replacement is blocked while any financial hold remains. Lock-in is recorded only after human verification of an external agreement, a verified creator reply and inbox receipt; there is no agent payment, contract-signing or publishing tool.

Verification: `.venv/bin/python -m pytest -q`, `node tests/ui_budget_flow.cjs`, `node tests/ui_creator_brief.cjs`, `node tests/ui_negotiations.cjs`. Three-worker tests mock the runtime and SMTP provider; they prove local coordination and budget behavior, not live runtime enforcement or delivery. No provider credentials or live model calls are needed to run these tests.
